# 22 - 水排序倒水动画核心算法

> 适用场景:新人接手。核心代码:`Assets/HotUpdate/WaterSort/WaterSortTubeRack.cs`
> (`PlayPourAsync` 及其辅助函数)、`Assets/Modules/WaterSort/UI/ws_liquid_soft.shader`。

## 1. 一句话概述

在 UGUI 上用**运行时几何 + 单个自定义 shader** 实现水排序玩法的倒水动画:
试管倾斜、水面全程保持水平、倾角由"液面恰好贴住瓶口"这一物理条件自动驱动、
倒出水量与目标管增量严格守恒,全程每帧只写 RectTransform 和材质向量,零物理引擎、零粒子。

## 2. 总体架构:先落子,后演动画(状态与表现分离)

```
点击试管 → 合法性预判(枚举引擎 LegalMoves) → 视图 TryPour 落子(盘面已变)
        → 上动画锁(_animating)→ PlayPourAsync 只负责"演过程"
        → 收尾:解锁 + 整架重建到真实盘面 + PourCompleted 广播(结算/引导在此补做)
```

- 盘面数据在动画开始前就是"终态",动画中所有液体几何都是**表现层**,收尾一次性重建,
  不存在"动画与数据双写"的一致性问题。
- 动画期挂起 `BoardChanged` 触发的整架重建(`Refresh` 检查 `_animating`),防止动画节点被销毁。
- 动画期锁死试管点击与 HUD 按钮:并发第二个倒水会在收尾重建时销毁对方动画握持的节点 →
  异常 + 锁死。这是实际踩过的坑。

## 3. 液体表示:同色 run 合并为"水平液带"(核心数据结构)

静置时液体 = 自底向上的色块列(每块一个 Image)。倒水前重组成**液带(band)**:

- 相邻同色块合并为一条带(带矩形取 run 最底块,合并后立即撑满整个 run 高度);
- 带记录轴向区间 `[a, b]`(管局部坐标,管心为原点)。

两个关键洞察:

1. **同色合并视觉无损**——同色块之间的界面本来就不可见,一条 3 格高的蓝带 ≡ 3 个蓝块;
2. **水平带模型保证层间稳定**——带是屏幕水平条带,任意倾角下"蓝永远整体在黄下方"。
   早期逐块方案在高倾角下色块沿管轴错开(色块并排而非叠放),是层间穿帮的根因。

## 4. 裁剪:遮罩 alpha 软裁,而不是 UGUI Mask(stencil)

- UGUI Mask 走模板缓冲,裁剪边是几何硬边无抗锯齿,试管底弧处呈像素阶梯;
- 自定义 shader `Box/UI/WaterSortLiquid`:液块是纯色 quad,片元阶段采样内腔剪影遮罩
  (`ws_tube_mask`)的 alpha,经 `smoothstep(EdgeLo, EdgeHi, m)` 软阈值裁剪;
- 每个液块通过材质向量 `_MaskST`(平移 + 缩放)把自己的 UV 映射到遮罩贴图空间,
  几何与采样框必须逐帧同步写(用 localScale 做液面动画会导致剪影变形,不可行)。

## 5. 旋转下"水面恒水平":三件套补偿(面试重点)

管体绕锚点旋转 θ 时,液体必须反向补偿,三件事缺一即穿帮:

1. **管根节点旋转 θ**(瓶身/玻璃随动);
2. **液带子节点反向旋转 −θ** → 带矩形在屏幕上保持轴对齐(水面水平);
3. **材质 `_MaskRot` 旋转补偿**:液带被反向旋转后,其 UV 采样框相对试管转了 −θ,
   片元采样遮罩前把 UV 绕"液带中心"旋回试管空间。

**关键的坑:旋转必须在等比空间做**。试管 96×400(1:4.2),归一化 UV 空间里转 32°
不是屏幕上的 32°——直接转会把采样区域扭得完全错位(液体露成方块/全消失)。
解法:x 方向先乘屏幕宽高比换算到"管高为单位"的等比空间,旋转后再换算回 UV 空间。

液带放置用**中心锚定**:带中心屏幕位 `(0, yCenter)` 反解管局部坐标
`x_c = y_c·tanθ, y_c = yCenter·cosθ`。注意 `x_c = yCenter·tanθ` 是错的
(屏幕 y 会放大 `sin²θ/cosθ + cos²θ` 倍,87° 时约 19 倍,整管水被按"未旋转"摆开、
底层带沉出管外被裁没)——这是实际出现过的 bug:分层、底层体积变小、像漂移出管外。
另:遮罩按片元真实管空间坐标采样,与带位置无关,所以摆错位置只影响"切哪一段",
不影响剪影形状本身。

## 6. 倾角模型:「液面钉唇口」条件驱动(面试最大亮点)

**不要用固定终角**。我们迭代过两版固定终角,各有各的假:

- 87°(近水平):水多的管子也被压平,水平液带全挤向管口一侧,观感"下层水顶到瓶口要涌出";
- 70°:水少的管子液面还没到口就开始出水,"水提前减少"。

正确做法是把出水角的几何解从"只算起点"改成"全程驱动":

```
液面是屏幕水平线(带模型),屏幕高 = 管心高 + surface·cosθ
令其恰等于唇口高度(唇口钉在锚点上,是定值)解得:

    |θ| = atan( 2·(h/2 − surface) / w )        —— LipTheta(surface)

surface(轴向液面)随倒出量单调下降 → θ 单调增大,水面始终钉在唇口:
    出水前:管子只倾到初液面贴唇口的出水角,液面没到口绝不倒水;
    倒水中:上层水正好从管口流出,下一层刚好挨着瓶口;
    倒完后:剩余液面正好停在瓶口位置,随即收管。
```

`PourMaxTiltDeg = 87°` 退化为绝对上限,只在近乎倒空时接近(倒最后一滴水本来就要转很平,
且此时水量极少,无"挤层"观感)。

配套约束:

- **滑移段预倾角 ≤ 出水角**(保证飞行途中水不涌出管口),同时封顶 30°
  (防少水管的出水角达 80°+ 时一路转到近水平);
- 出水角也决定"水流柱何时出现":液面触唇口才生成水流,视觉逻辑自洽。

## 7. 水量守恒与部分转移

- 转移量 `count` 来自引擎 `LegalMoves`(= min(顶层同色 run 长度, 目标剩余空间));
- 目标管生长块高度 `count·单格高` 与源管顶带"管口侧消减量"按 `unitSrc/unitDst` 比例
  逐帧换算,严格等量;
- **部分转移(count < runLen)必须用真实初液面** `bandB[last]`,不能按"带底 + count"反推:
  后者会低估液面 → 起手液面跳变一格、顶带被整条倒空、收尾重建时未倒的余量"凭空弹回"
  (水不守恒穿帮)。源管顶 3 红、目标只装得下 2 是最常见的触发场景。

## 8. 动画节奏(四段式)

| 段 | 内容 | 时长 |
|---|---|---|
| 1 滑移 | 边移动边旋转到预倾角(≤出水角),前沿角送到目标口上方锚点 | 0.14s |
| 2 倾倒 | 先倾到出水角(不出水)→ 出水后倾角随液面自动加大;水流柱 + 源管消减 + 目标生长同步 | 0.30s × count |
| 3 收管 | 不沿原弧,从倾倒终态直接插值回基准位(位置 + 旋转 + 液带同步) | 0.18s |

- 倾倒时长与份数线性放大 → **旋转角速度随份数放慢、单份流速恒定**(多倒不多流);
- 一次性动画驱动器 `Tween01`:归一进度 t 按 `Time.deltaTime` 累加,每帧回调,
  UniTask + `destroyCancellationToken` 取消(视图销毁时动画安全中止)。

## 9. 工程细节清单

- **零 GC 热路径**:每帧只写 RectTransform 的 position/rotation/sizeDelta 和材质向量;
- **材质实例管理**:静置液块按 (层数, 层序) 缓存派生材质(合批友好),缓存键须包含管高
  (分辨率变化 → 布局变化 → 旧实例的采样框全错);动画期克隆的临时材质统一登记,
  收尾显式 `Destroy`(节点 Destroy 不会回收材质,不显式销毁 = 每次倒水泄漏);
- **动画量与盘面解耦**:动画只演"过程",结果以收尾重建为准,允许动画模型做视觉近似
  (如分层贴管、不模拟真实流体);
- **中途取消安全**:临时节点随整架销毁,临时材质由 OnDestroy 兜底回收,
  `_animating` 用 catch-all 保证必然解锁。

## 10. 踩坑复盘(面试加分项)

1. **液带中心反解因子错误**:`x_c = yCenter·tanθ` → 屏幕位放大近 19 倍,分层/漂移出管外;
2. **合带后未立即撑满**:多格同色 run 在滑移段显示成 1 格("3 蓝变 1 蓝");
3. **水流柱顶点取管口中心**:高倾角时高出真实唇口约半个管宽,应取钉死的锚点高度;
4. **结算时机**:通关事件在落子瞬间同步发出,结算弹窗会抢在最后一手动画结束前弹出,
   需要压住到动画收尾(`PourCompleted`)再弹;
5. **固定终角的两版失败迭代**(87° 挤层 / 70° 提前出水)→ 最终收敛到"物理条件驱动参数"
   的思路:让几何约束(液面贴唇口)决定动画,而不是拍一个魔法数字。

## 11. 一段话版本(电梯演讲)

> 倒水动画的全部难点在于"水面必须始终水平"。我们把液体重组为屏幕水平条带,
> 管体旋转 θ、条带反向旋转 −θ、再在 shader 里对遮罩采样做等比空间的旋转补偿,
> 三层补偿缺一不可;倾角不拍固定值,而是由"液面恰好贴住瓶口"这个物理条件实时解出,
> 于是水多的管子小角度就出水、快空的管子自然转到近水平,全程水量严格守恒。
> 状态与表现彻底分离:盘面先落子,动画只演过程,收尾一次性重建,天然不会出现表现与数据不一致。
