## 0. 核心结论(先看这张表)

**"新增玩法" = 照抄 `Assets/HotUpdate/Sudoku/` 的目录模式,不是在框架上新搭东西。**
现有骨架已具备玩法组件化的全部管线,新增玩法的代码/资源/清单是**复制 + 改名 + 补 3 行配置**的体力活。

| 能力 | 现状 | 新增玩法时 |
|---|---|---|
| 玩法独立程序集 | ✅ `Box.HotUpdate.Sudoku`(asmdef 范本) | 复制改名为 `Box.HotUpdate.<Game>` |
| 模块入口 | ✅ `IGameModule` + `SudokuModule` 范本 | 新玩法实现 `IGameModule`,`Id => "<game>"` |
| 模块清单驱动 | ✅ `ModuleCatalog.asset` + `ModuleLoader`(反射实例化) | **清单加 1 条**(推荐走 `AddEntry`) |
| 资源按组管理 | ✅ Addressables:`Core`/`UI_Local`/`Art_Audio` | prefab 进 `UI_Local`;远程玩法资源可建独立组 |
| 服务抽象 | ✅ `Box.Services.Abstractions`(存档/偏好/资源) | 直接用,存档自动按玩法 id 分区 |
| UI 路由/弹窗 | ✅ `UIService.Router` + `AddressablesViewLoader` | 照 View 范本实现 `UIView` 子类 |

## 2. 新增玩法七步落地(以井字棋 TicTacToe 为例)

### 步骤 1:代码层 —— 新建玩法文件夹 + 程序集

```
Assets/HotUpdate/TicTacToe/
├── Box.HotUpdate.TicTacToe.asmdef   ← 复制 Sudoku 版改名,引用列表照抄
├── TicTacToeModule.cs               ← 模块入口(照 SudokuModule.cs)
├── TicTacToeView.cs                 ← 玩法主视图(照 GameplayView.cs,UIView 子类)
├── TicTacToeRules.cs                ← 玩法规则(纯逻辑类,方便测试)
└── ...
```

`Box.HotUpdate.TicTacToe.asmdef` 引用(照抄 Sudoku,游戏逻辑依赖单独拆 `TicTacToe.Core` 可选):

```json
{
    "name": "Box.HotUpdate.TicTacToe",
    "rootNamespace": "Box.HotUpdate.TicTacToe",
    "references": [
        "Box.ModuleFramework",
        "Box.Services.Abstractions",
        "Box.UI",
        "UniTask",
        "Unity.TextMeshPro"
    ],
    "includePlatforms": [],
    "autoReferenced": true
}
```

模块入口(`TicTacToeModule.cs`),中间态 = OnEnter 切玩法场景 / OnExit 回大厅:

```csharp
public sealed class TicTacToeModule : IGameModule
{
    public string Id => "tictactoe";

    public UniTask OnEnter(ModuleContext ctx)
    {
        SceneManager.LoadSceneAsync("TicTacToe");
        return UniTask.CompletedTask;
    }

    public UniTask OnExit()
    {
        SceneManager.LoadSceneAsync("MainMenu");
        return UniTask.CompletedTask;
    }
}
```

> **纪律**:玩法程序集**不得反向引用**壳层(`Box.Gameplay`)与大厅;只依赖 `ModuleFramework` / `Services.Abstractions` / `UI`。这样 v1.1 热更下发时边界不变。

### 步骤 2:资源层 —— Prefab 进 Addressables

- prefab 放 `Assets/UI/Prefabs/TicTacToe/TicTacToeView.prefab`(不进 Resources!)
- 加入 **`UI_Local` 组**(首包内),Addressables 地址 `UI/TicTacToeView`
- 若玩法想 v1.1 远程下发:新建独立组 `Game_TicTacToe`(按玩法分组,预算 ≤8MB),构建 Profile 与更新组按 11 文档 §3.3 配
- 玩法弹窗(如结算)放 `Assets/UI/Prefabs/Popups/`,地址 `UI/Popups/xxx`

### 步骤 3:清单层 —— ModuleCatalog 加 1 条(推荐走 AddEntry)

**推荐做法**:玩法侧 Editor 脚本调泛化入口(已入库,见 `Phase45ModuleSetup.AddEntry`):

```csharp
// Assets/Editor/TicTacToeModuleSetup.cs(玩法仓库自带,幂等)
public static class TicTacToeModuleSetup
{
    [MenuItem("TicTacToe/Setup Module Entry")]
    public static void Build()
    {
        var catalog = AssetDatabase.LoadAssetAtPath<ModuleCatalog>(
            "Assets/Resources/Config/ModuleCatalog.asset");
        if (catalog == null) { /* 先执行 Phase45ModuleSetup.Build */ return; }
        Phase45ModuleSetup.AddEntry(
            catalog, "tictactoe", "Box.HotUpdate.TicTacToe.TicTacToeModule",
            "TicTacToe", "井字棋", sortOrder: 1);
        AssetDatabase.SaveAssets();
    }
}
```

等价手改 `ModuleCatalog.asset` 追加条目:

```yaml
- id: tictactoe
  entryType: Box.HotUpdate.TicTacToe.TicTacToeModule
  entryScene: TicTacToe
  displayName: 井字棋
  enabled: 1
  sortOrder: 1
```

> `id` 即 `ModuleLoader.EnterAsync` 的键 + 埋点前缀(`{id}.{action}`,11 文档 §8.4);`entryType` 必须全名,`link.xml` 保留。

### 步骤 4:场景 + 构建配置

- 新建 `Assets/Scenes/TicTacToe.unity`(或后续单场景化后以 prefab 入口替代,11 文档决策 B)
- 加入 `EditorBuildSettings`(和 `MainMenu`/`Gameplay` 并列),否则构建缺场景
- 玩法逻辑不需要大厅参与:大厅只调 `EnterAsync("tictactoe")`

### 步骤 5:link.xml 保留入口类型(IL2CPP 防线)

`Assets/link.xml` 追加(否则 IL2CPP 裁剪可能让反射 `Type.GetType` 返回 null):

```xml
<assembly fullname="Box.HotUpdate.TicTacToe">
    <type fullname="Box.HotUpdate.TicTacToe.TicTacToeModule" preserve="all"/>
</assembly>
```

### 步骤 6:测试

- 玩法规则类(纯逻辑):照 `Sudoku.Core.Tests` / `Box.Gameplay.Tests` 建 EditMode 测试程序集
- 模块装载:照 `ModuleLoaderTests` 验证 `EntryType` 可反射实例化
- 回归:CLI 跑 EditMode 全量(命令见 §6),**基线 139 用例不得下降**

### 步骤 7:构建验证

```powershell

& "C:\Program Files\Unity\Hub\Editor\6000.3.20f1\Editor\Unity.exe" -batchmode -quit `
```

- 首包仍 **≤60MB**(现 42.35MB,余量 ~17MB)
- 验证 `[BuildScript] SUCCESS` 与 `Exiting batchmode successfully now!`

## 3. 玩法文件夹模板(可整体复制)

```text
Assets/HotUpdate/<Game>/
├── Box.HotUpdate.<Game>.asmdef        (引用 ModuleFramework/Services.Abstractions/UI/UniTask/TMP)
├── <Game>Module.cs                    (IGameModule:Id/OnEnter/OnExit)
├── <Game>View.cs                      (UIView:玩法主界面,走 Addressables 加载)
├── <Game>Rules.cs                     (纯逻辑,零 UnityEngine 依赖=可单测)
├── <Game>Settings.cs                  (玩法内偏好,经 ISettingsService 分区存取)
└── [可选] <Game>Core.csproj / <Game>.Tests.csproj

Assets/UI/Prefabs/<Game>/…             (玩法视图 prefab,Addressables UI_Local 组)
Assets/Scenes/<Game>.unity             (中间态玩法场景)
Assets/Editor/<Game>ModuleSetup.cs     (清单 AddEntry + link.xml 维护,幂等)
```

**每玩法固定开销(除玩法逻辑本身)**:1 asmdef + 3 脚本(入口/视图/规则)+ 1 prefab + 1 场景 + 1 清单条目 + 1 link.xml 行 ≈ **1 天**;玩法逻辑与 UI 打磨另计(2~4 天/玩法)。

## 4. 组件化边界纪律(新增玩法必须遵守)

| 规则 | 说明 | 违反后果 |
|---|---|---|
| 只依赖框架层,不依赖壳层 | 玩法程序集引用 ≤ `ModuleFramework`/`Services.Abstractions`/`UI` | v1.1 拆热更 dll 时边界断裂,被迫重写 |
| 不引用其他玩法程序集 | 玩法间交叉导量走大厅/服务层,不直接引用 | 玩法耦合,单包热更失败 |
| 存档用分区键 | `SaveService` 已按模块分区,玩法存 `tictactoe.*` | 跨玩法数据污染,清档误伤 |
| 资源不进 Resources | prefab/美术走 Addressables 组 | 失去热更/分组/瘦身能力,体积膨胀 |
| 入口类型进 link.xml | 反射实例化依赖类型保留 | IL2CPP 下 `Type.GetType` 返回 null,玩法无法启动 |
| 测试程序集独立 | 规则类零引擎依赖,可快速单测 | 玩法逻辑测试成本上升,回归失守 |

## 5. 大厅动态化(第二玩法前的临门一脚,推荐做)

现状:`MainMenuView` 硬编码 `StartButton`/`DailyChallengeButton` 两个 sudoku 按钮(注释自述"网格留给第二玩法")。
加第二玩法前把它改成**读 `ModuleCatalog.entries` 动态生成入口网格**:

- 遍历 `ModuleLoader.Entries`(`enabled == true`,按 `sortOrder` 排序)
- 每条目生成一个入口按钮 → `EnterAsync(entry.id, null)` / 每日挑战按约定传参
- 文案 `displayName` 接 L10n 本地化 key(Phase 5 L10n 已就绪)
- 完成后:**新玩法 = 清单 1 条 + 资源 + 场景,大厅零改动**,组件化闭环

工作量约半天。做完后本文 §2 步骤 3 可再简化(连大厅侧都不用动)。

## 6. 常用 CLI 命令

```powershell
# ① 编译/资产校验(任何新增后必跑,确认无 error CS)
& Unity.exe -batchmode -quit -projectPath "…\GameBox" -logFile "…\compile.log"

# ② EditMode 全量回归(-runTests 禁加 -quit,Phase 6 教训)
& Unity.exe -batchmode -projectPath "…\GameBox" -runTests -testPlatform EditMode `
  -testResults "…\TestResults\newgame.xml" -logFile "…\tests.log"

# ③ 玩法清单条目(玩法侧脚本)
& Unity.exe -batchmode -quit -projectPath "…\GameBox" `
  -executeMethod TicTacToeModuleSetup.Build -logFile "…\entry.log"

# ④ AAB/APK 构建(含 Addressables 内容构建)
& Unity.exe -batchmode -quit -projectPath "…\GameBox" `
  -executeMethod BuildScript.BuildAndroidAab -logFile "…\aab.log"
```

> Windows 下 Unity.exe 是 GUI 程序,PowerShell 立即返回属正常;用新 PID + `Wait-Process` 等待,再 Select-String 日志验证(Phase 6 定型方式②)。
