# 07 — Unity 2022 落地版最小开发路线图

> 版本:v1.3 | 状态:Draft
> 适用对象:单人开发、已有 Unity 环境、目标是用项目学习海外休闲游戏完整流程并形成求职作品
> **引擎基线更新(2026-08-20)**:执行基线已从 Unity 2022 迁移到 **Unity `6000.3.20f1`(国际版)**(11 号 D-12 / §4.9)。**文件名中的"Unity2022"仅为历史标题**,本文的 MVP 裁剪思路、阶段目标与上架流程与引擎版本无关,继续有效;§2 中"为什么先用 Unity 2022"一节按下方说明理解。
> **对齐说明(对齐 11 号 v2.2)**:本文"首版不采用代码热更"与 11 号的 **v1.0 纯 AOT 自包含策略一致**(HybridCLR 只做程序集拆分与构建管线,首版**不启用解释执行、不做远程下发**,见 11 号 §0 D-2);盒子化架构(程序集拆分、ModuleFramework、`UIKit`、Trait、热更管线、预算与数据门控)以 11 号方案为准。

---

## 1. 这份路线图解决什么问题

现有 [06_项目路线图.md](./06_项目路线图.md) 更适合“准备做可软启动商业产品”的完整方案。

这份文档提供一个**Unity 2022 可直接开干的最小落地版路径**，目标不是一开始把所有商业功能做满，而是先用最短路径跑通下面这条链路：

**可玩原型 → 垂直切片 → 可发布 MVP → 小规模测试 → 复盘沉淀作品集**

核心原则:
- 优先学习海外休闲游戏流程，不优先追新引擎。
- 优先形成可展示作品，不优先堆功能数量。
- 优先做完整闭环，不优先接入所有平台能力。

## 2. 引擎与技术策略

### 2.1 引擎选择的历史与现状

**原判断(2026-08 之前)**:本地已有 Unity 2022,可立即开始;对数独这类 UI + 纯逻辑项目已足够覆盖 Android、AAB、IL2CPP、广告、IAP、Firebase、自动化构建;当时最需要补的是**海外休闲游戏交付流程**,不是引擎新特性。

**现判断(2026-08-20 起,已改)**:项目从"单机数独 MVP"演进为"盒子化长期运营"(11 号方案),因此引擎标准也变了:

- 原基线是 Unity **中国版 c1 分支**,而项目是出海产品 → 换**国际版**,少一层排障变量
- 2022 LTS 已过官方支持窗口,而 Play 的 targetSdk 要求每年上调 → 长期运营吃不住
- 工程当前只有 4 个 asmdef / 2 个场景 / 无 Addressables 无 HybridCLR → **现在是迁移成本最低的时刻**

→ 定版 **Unity `6000.3.20f1`(国际版)**,迁移放在 P-1,步骤与验收见 11 号 §4.9。

### 2.2 版本策略

- **开发版本**:**Unity `6000.3.20f1`(国际版)** —— 2026-08-20 定版,见 [11_Unity游戏盒子架构方案.md](./11_Unity游戏盒子架构方案.md) §4.9
- **发布平台**:Android Google Play
- **迁移策略**:迁移在 P-1 完成(副本验证 → 验收通过 → 主工程切换);此后引擎版本变更一律走 §4.9 的排除法,不随意跟随新版本

### 2.3 技术裁剪原则

以下能力首版保留:
- 纯 C# 的 `SudokuCore`
- UGUI + TextMeshPro
- Android AAB 打包
- AdMob 激励视频
- Unity IAP 去广告
- Firebase Analytics + Crashlytics

以下能力首版延后:
- GPGS 成就/排行榜/云存档
- Remote Config + A/B 测试
- 订阅
- 10 语言本地化
- Banner 和插屏广告

补充决策:
- 首版**不启用代码热更**(不做解释执行、不做远程 dll 下发);但若走盒子路线,程序集**按 11 号方案 §4.4 提前拆好**并以纯 AOT 模式出包 —— 拆分本身成本很低,后续切换零代码改动,不拆则等于把重构成本留到用户量最大的时候。

## 3. 最小目标定义

### 3.1 项目目标

这不是“先做大而全商业数独”，而是“先完成一款符合海外休闲游戏方法论的最小作品”。

### 3.2 最小可交付成果

完成以下 5 项，即可视为第一阶段成功:

1. 玩家可以顺畅完成一局数独。
2. 应用可在 Google Play Internal Testing 正常安装和运行。
3. 激励广告和去广告内购至少各有一条可跑通链路。
4. 有基础埋点和崩溃监控，可做数据复盘。
5. 你能整理出一份项目总结，说明产品定位、技术架构、商业化思路、测试和发布过程。

## 4. MVP 范围重定义

### 4.1 首版必须做(P0)

- 标准 9x9 数独
- 3 个难度档位:Easy / Medium / Hard
- 填数、擦除、笔记
- 撤销
- 错误检测开关
- 高亮
- 计时与单局结算
- 本地统计:总局数、完成数、最佳时间
- 基础新手引导
- 激励视频广告 1 个点位:提示用尽后获取 1 次提示
- 去广告 IAP 1 个商品
- 隐私政策入口
- UMP 同意流程
- Firebase Analytics + Crashlytics
- Android AAB 打包与 Internal Testing 发布

### 4.2 首版明确不做

- 每日挑战
- Streak
- 成就/排行榜
- 云存档
- 插屏广告
- Banner 广告
- 订阅
- 讲解式提示
- 10 语言本地化
- 主题商店
- 变体数独

### 4.3 第二阶段再补(P1)

- 每日挑战
- Streak
- 深色模式完善
- 插屏广告频控
- 更多统计项
- 5 种以内核心语言本地化
- Remote Config

## 5. 四阶段最小路线图

## 阶段 A — 原型周(第 1-2 周)

目标:证明核心玩法和算法成立。

任务:
- 建立 Unity 2022 项目骨架。
- 创建 `SudokuCore` 纯 C# 模块。
- 实现求解器、生成器、唯一解校验。
- 做最简盘面:选格、填数、胜利判定。
- 补 20 到 50 个核心单元测试。

退出门槛:
- 任意难度谜题可生成、可解、可完成。
- 生成耗时在可接受范围内，无明显卡顿。
- 核心逻辑不依赖 Unity API。

建议输出物:
- 1 个可录屏演示的原型场景。
- 1 份算法说明，后续可用于面试表达。

## 阶段 B — 垂直切片(第 3-4 周)

目标:跑通一条完整单局体验。

任务:
- 加入笔记、撤销、错误检测、高亮、计时。
- 完成主菜单、难度选择、结算弹窗。
- 完成基础设置页。
- 加入首次启动引导。
- 打出第一版 Android 真机包。

退出门槛:
- 从启动到完成一局，全流程无阻断。
- 安卓真机上 UI 正常、输入顺畅。
- 你可以把这版给外部朋友试玩。

建议输出物:
- 1 个 3 到 5 分钟试玩视频。
- 1 份第一轮试玩记录表。

## 阶段 C — 可发布 MVP(第 5-8 周)

目标:从“可玩”进入“可发布测试”。

任务:
- 接入 AdMob 激励视频。
- 接入 Unity IAP 去广告。
- 接入 UMP 同意流程。
- 接入 Firebase Analytics 和 Crashlytics。
- 增加基础统计与关键埋点。
- 补齐隐私政策页、数据说明、商店基础素材。
- 打 AAB，走 Google Play Internal Testing。

退出门槛:
- 安装 → 同意隐私 → 开局 → 完成 → 看激励广告 → 返回主菜单，全链路可跑。
- 去广告购买和恢复购买可正常验证。
- Crashlytics 和核心埋点可以看到数据。

建议输出物:
- 1 个 Internal Testing 安装包版本。
- 1 份埋点事件表。
- 1 份发布检查清单。

## 阶段 D — 小规模验证与复盘(第 9-10 周)

目标:先学流程，再决定要不要继续做商业版。

任务:
- 邀请 10 到 30 个测试者试玩。
- 收集首局完成率、提示使用率、广告完成率、购买点击率。
- 记录 UI 问题、难度问题、广告打断感。
- 修 1 轮高优先级问题。
- 输出复盘文档。

退出门槛:
- 你能明确说出这款产品当前的 3 个优点和 3 个短板。
- 你能基于真实试玩或测试数据决定下一步是继续软启动，还是转成作品集项目。

建议输出物:
- 1 份版本复盘。
- 1 份求职作品说明稿。

## 7. 你现在最小需要的技术栈

| 类别 | 建议 | 说明 |
|---|---|---|
| 引擎 | Unity `6000.3.20f1`(国际版) | 见 §2.1/§2.2 与 11 号 §4.9 |
| UI | UGUI + TMP | 足够稳定 |
| 核心逻辑 | 纯 C# 类库 + asmdef | 保证可测试、可迁移 |
| DI | 可选,先不强制 | 首版不必一开始引入复杂容器 |
| 异步 | 协程优先 | 首版用最熟悉的方案即可 |
| 响应式 | 首版不强制 | 降低理解和维护成本 |
| 分析 | Firebase Analytics | 先满足埋点和事件查看 |
| 崩溃 | Crashlytics | 海外上线基础能力 |
| 广告 | AdMob Rewarded | 先接最核心变现点 |
| IAP | Unity IAP | 满足去广告购买 |

说明:
- 如果你想学习更企业化的结构，可以在第二阶段再引入 VContainer / UniTask。
- 但对当前项目来说，**先跑通闭环比先上完整架构更重要**。

## 8. 最小 KPI，不追求一开始就达标

这阶段不建议直接把正式软启动 KPI 当硬目标，而是先看这些更现实的指标:

| 指标 | 第一阶段目标 |
|---|---|
| 首局完成率 | ≥ 60% |
| 崩溃率 | 无明显阻断崩溃 |
| 激励广告完成率 | 能稳定触发和回奖 |
| 去广告点击率 | 有初步点击数据即可 |
| 试玩反馈 | 能收集到明确的体验问题 |

当这些基础指标稳定后，再进入 D1、D7、ARPDAU 这类软启动指标。

## 10. 推荐的下一步行动

如果你现在就开始做，顺序建议固定为:

1. 建 Unity 2022 工程和目录结构。
2. 先只做 `SudokuCore` 和最小盘面。
3. 真机跑通单局。
4. 再接广告、IAP、Firebase。
5. 最后再碰 Google Play 发布和商店素材。

这条路径更符合你当前的目标:
- 能学到海外休闲游戏的关键流程。
- 能避免一开始被复杂 SDK 和范围拖垮。
- 能较快形成一个可展示、可复盘、可用于求职讲述的作品。
