## 0. 发布路径（先看这个，决定其余项的先后）

```
生产权限获批（✅ 2026-09-16）
   ↓
出 v17（含下方 §1 全部代码改动 + 真实广告位）
   ↓
上传 Play Console → 生产轨道 → 全量发布
   （★ 首版没有灰度选项，理由见 §3.1）
   ↓
商店页对公众公开 ← ★ 关键解锁点
   ↓
AdMob 后台「添加商店链接」→ 等就绪度审核获批
   ↓
广告自动开始填充（真 ID 已在包里，无需再发版）
   ↓
观察崩溃率/评分 → 有问题只能下架或快速跟一个修复版
```

**★ 关键点**：AdMob 就绪度审核的前提是商店页公开可访问，而商店页只在生产轨道上线后才公开。
所以**不能等 AdMob 批准再发版**——那样永远等不到。正确顺序是**先发版带真 ID，再关联 AdMob**。

### 2026-09-16 · 隐私政策补正（Data Safety 被 Console 打回）

**触发**：填完 Data Safety 表单后启动生产发布，Console 报「数据收集和安全性填写的不对」。

**根因**：表单勾了「大致位置」，而隐私政策第 1 节写
`The App has no account system and requests no contact/location/photo permissions`
（中文本同理）——**一边声明收集、一边否认**。这种自相矛盾比两边都漏更容易被打回。

依据 Google 官方 AdMob 数据披露表：AdMob 收集 **IP 地址**，并"可能用于估算设备的大致位置"。
**关键认知：这与应用是否申请定位权限无关。** 工程 manifest 确为零定位权限
（只有 `INTERNET` / `ACCESS_NETWORK_STATE` / `FOREGROUND_SERVICE` / `WAKE_LOCK`
+ `ACCESS_ADSERVICES_*` + `AD_ID`），但「没申请权限」≠「没收集位置」。

**改动**：[privacy-policy.html](./privacy-policy.html)

- 中英两版表格补齐为六行，与表单四类一一对应：设备 ID / **大致位置** / 应用活动 /
  崩溃与诊断 / 本地存档 / 敏感信息
- 矛盾句改为区分两件事：**不申请定位权限**（事实）与 **SDK 依据 IP 推算大致位置**（事实），
  二者并存不冲突
- 补上原文缺失、但表单必问的三条：**共享**（是，给 Google）、**加密传输**（HTTPS/TLS）、
  **删除途径**（邮件 `slx97065227@gmail.com`）——原先只写「卸载即删」，
  那只覆盖本地存档、覆盖不了 SDK 持有的数据，表单问「可否删除」时是答不上的
- Last Updated → `2026-09-16`（生效日期保持 `2026-08-29` 不变）

同步更新 [15 号文档 §4.1](./15_Phase7商业化执行清单.md)：填法定稿为四类 + 子项勾选表 +

**教训**：隐私政策与 Data Safety 表单是**同一份事实的两种表述**，必须逐条对齐。
表单里勾了什么，政策里就必须能找到对应句子；政策里否认了什么，表单里就不能勾。
以后任何一侧变动，另一侧必须同批改。
