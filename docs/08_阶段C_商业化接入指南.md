# 08 — 阶段 C 商业化接入指南(新手向)

> 版本:v1.0 | 状态:Draft
> 目标读者:第一次接触「广告变现 / 内购 / 数据分析」的开发者
> 配套代码:本指南对应 `Assets/Features/Gameplay/Services/` 下的服务层代码

---

## 0. 这份文档解决什么问题

阶段 C 要做的事,用一句话说:

> 把一个「能玩的数独」,变成「能赚钱、能上架 Google Play 的海外休闲游戏」。

它包含**三条链路**:

| 链路 | 用什么 | 干什么 | 赚钱/价值 |
|---|---|---|---|
| ① 激励视频广告 | Google AdMob | 玩家提示用完了 → 看一段广告 → 获得提示 | 广告分成(主要收入) |
| ② 去广告内购 | Unity IAP(Google Play Billing) | 玩家花 3.99 美元永久去掉广告 | 直接收入 |
| ③ 数据埋点 + 崩溃 | Firebase | 记录玩家行为、崩溃日志,用来优化和复盘 | 决策依据 |

**关键设计:代码已经写好,而且「不装任何 SDK 也能先跑通流程」。** 下面第 3 节会讲为什么。

---

## 1. 先搞清楚几个概念(给没接触过的人)

### 1.1 什么是「变现」
让玩家免费玩,但通过广告或付费赚回钱。休闲益智游戏付费意愿低,所以**广告是主要收入,内购是补充**。

### 1.2 激励视频(Rewarded Video)
玩家**主动选择**看一段 15~30 秒的视频广告,看完后获得奖励(比如一次提示)。这是体验最好的广告形式,因为玩家是自愿的。

### 1.3 非消耗型商品(Non-Consumable)
「去广告」属于非消耗型:买一次,**永久有效**,换手机/重装也能恢复。对应 Google Play 里的「应用内商品」。

### 1.4 GDPR 同意(为什么欧洲玩家要先弹窗)
欧盟《通用数据保护条例》规定:收集用户数据(广告 SDK 会用到设备标识)前,必须**征得用户同意**。所以欧洲玩家第一次打开游戏,要先弹一个「是否同意个性化广告」的窗口。这个弹窗由 **UMP**(Google User Messaging Platform)自动处理。

### 1.5 埋点(Event)
在关键行为处记录一条日志,比如「开局」「完成一局」「用了提示」。后台聚合后能算出**留存率、变现效率**等指标。埋点不是监控玩家隐私,而是看「整体趋势」。

### 1.6 几个常见指标(先认识,后面再看)
- **eCPM**:每 1000 次广告展示赚多少钱(美元),衡量广告价值。
- **D1/D7 留存**:第 1 天/第 7 天还回来的玩家比例,衡量游戏黏性。
- **转化率**:付费玩家占玩家的比例。

## 2. 我写的代码是怎么组织的(架构)

### 2.1 一张图看懂

```
控制器 / 设置页(业务逻辑)
        │  调用接口
        ▼
  Services(定位器) ────── 根据编译开关选择 ──────┐
        │                                        │
        ├── IAdsService      →  桩实现 或 真 AdMob 实现
        ├── IIapService      →  桩实现 或 真 Unity IAP 实现
        └── IAnalyticsService →  桩实现 或 真 Firebase 实现
```

### 2.2 核心思想:接口 + 桩 + 真实现

- **接口**(`ServiceInterfaces.cs`):定义「能做什么」,不管「怎么做」。上层代码只认识接口。
- **桩实现**(`StubServices.cs`):假的实现。广告直接「模拟看完发奖励」,内购直接「模拟购买成功」,埋点打印到 Console。
- **真实现**(`AdMobAdsService.cs` / `UnityIapService.cs` / `FirebaseAnalyticsService.cs`):接真 SDK,被 `#if` 编译开关包住。

### 2.3 编译开关是什么

代码里有这样的结构:

```csharp
#if SUDOKU_ADMOB
    Ads = new AdMobAdsService();   // 真实现(装了 AdMob 才编译)
#else
    Ads = new AdsServiceStub();    // 桩实现(默认)
#endif
```

- **没定义符号**(默认):编译桩实现 → 不装 SDK 也能运行。
- **定义了符号**:编译真实现 → 需要先装好对应 SDK。

符号在哪定义:`Player Settings → Player → Scripting Define Symbols`,输入符号名,多个用分号分隔(如 `SUDOKU_ADMOB;SUDOKU_IAP`)。

### 2.4 文件清单

| 文件 | 作用 | 需要 SDK 吗 |
|---|---|---|
| `ServiceInterfaces.cs` | 三个接口 | 否 |
| `StubServices.cs` | 三个桩实现 | 否 |
| `Services.cs` | 定位器,按开关选择实现 | 否 |
| `AppBootstrap.cs` | 启动时初始化服务 | 否 |
| `AdMobAdsService.cs` | 真 AdMob + UMP | 是(AdMob) |
| `UnityIapService.cs` | 真 Unity IAP | 是(IAP) |
| `FirebaseAnalyticsService.cs` | 真 Firebase | 是(Firebase) |

## 3. 先跑通流程(零 SDK,现在就能做)

**你现在不用装任何东西**,因为桩实现已经能模拟完整链路。打开 Unity 进 Play 模式验证:

1. 玩一局,把 3 个提示用完;
2. 再点「提示」→ Console 会打印 `[AdsStub] 模拟激励视频:直接视为看完并发放奖励`,然后自动给一次提示;
3. 主菜单 → 设置 → 点「恢复购买」→ Console 打印 `[IapStub] 模拟恢复购买`;
4. Console 里能看到 `[AnalyticsStub] 事件:session_start`、`level_start`、`level_complete` 等埋点。

> **这一步的价值**:先确认「提示→看广告→回奖」「购买→去广告」这些**业务逻辑是对的**,再接真 SDK。真 SDK 只替换底层实现,业务逻辑一行不用改。这就是「接口解耦」的好处。

## 4. 链路一:激励视频广告(AdMob + UMP)

### 4.1 准备:AdMob 账号和广告位

1. 注册 [Google AdMob](https://admob.google.com/)(需要 Google 账号)。
2. 创建应用 → 创建**激励视频广告位**,拿到形如 `ca-app-pub-XXXXXXXXXXXX/YYYYYYYYYY` 的**广告位 ID**。
3. 把 ID 填进 `AdMobAdsService.cs` 的 `RewardedAdUnitId`(开发阶段可先用代码里的官方测试 ID,不产生真实收益)。

### 4.2 安装 SDK

- 从 [Google Mobile Ads Unity 插件](https://github.com/googleads/googleads-mobile-unity/releases) 下载 **官方最新主线 v11.x**(当前 **v11.4.0**,2026-08 时点)的 `.unitypackage`,双击导入 Unity。
- 导入后确认 Assets 下出现 `GoogleMobileAds` 目录;依次执行 `Assets → External Dependency Manager → Android → Resolve`。

> **Unity 6(6000.3)时点注记(2026-08-23)**:官方最新版本已到 **v11.x**,内置 UMP 与 EDM4U 1.2.188,
> 无需再单独安装 UMP。本文代码讲解基于 **v8.x** 旧 API,**仅作接口与业务逻辑参考**;
> 写 `AdMobAdsService.cs` 真实现时按 v11 新 API(事件签名已从 `EventHandler<T>` 改为 `Action<T>`,
> 且 Next-Gen SDK 要求 `MobileAds.Initialize()` 在主线程调用),具体以官方文档为准。
> 完整落地清单见 [15_Phase7商业化执行清单.md](./15_Phase7商业化执行清单.md)。

### 4.3 定义编译符号

`Player Settings → Scripting Define Symbols` 加 `SUDOKU_ADMOB`。此时 `AdMobAdsService.cs` 才会参与编译。

### 4.4 代码讲解(逐段)

`AdMobAdsService.cs` 的完整流程:

1. **Initialize()** → `RequestConsentThenInit()`:先处理同意。
2. **UMP 同意**:`ConsentInformation.Update(...)` 向 Google 查询该用户是否需要同意;需要的话用 `ConsentForm.LoadAndShowConsentFormIfRequired(...)` 弹窗。
3. **初始化广告**:`MobileAds.Initialize(...)`。
4. **加载激励视频**:`LoadRewardedAd()` 创建 `RewardedAd`,订阅三个事件:
   - `OnUserEarnedReward`(看完广告)→ 回调 `true` 发奖励;
   - `OnAdClosed`(广告关闭)→ 预加载下一条;
   - `OnAdFailedToShow`(展示失败)→ 回调 `false` 不发奖励。
5. **展示**:`ShowRewardedAd(onReward)` 里调 `_rewardedAd.Show()`。

### 4.5 在游戏里怎么触发

`SudokuGameController.TryUseHint()` 里:

- 提示币 > 0 → 直接给提示;
- 提示币 = 0 且**没买去广告** → 调 `Services.Ads.ShowRewardedAd(...)`,看完奖励一次提示;
- 提示币 = 0 且**买了去广告** → 直接给提示,不打扰。

### 4.6 真机测试必须加「测试设备」(重要!)

开发阶段在真机上看到的是**测试广告**,但如果你用真机跑真实广告流程,必须在代码里把你的设备注册为测试设备,否则可能被 AdMob 判定为违规。方法:

```csharp
// 在 MobileAds.Initialize 之前:
var requestConfiguration = new RequestConfiguration.Builder()
    .SetTestDeviceIds(new System.Collections.Generic.List<string> { "你的设备ID" })
    .build();
MobileAds.SetRequestConfiguration(requestConfiguration);
```

设备 ID 会在第一次加载广告时打印到 Logcat(形如 `Use RequestConfiguration...`)。

## 5. 链路二:去广告内购(Unity IAP)

### 5.1 准备:Google Play Console 和商品

1. 注册 [Google Play Console](https://play.google.com/console/)($25 一次性注册费)。
2. 创建应用 → 左侧「应用内商品」→ 创建商品:
   - 商品 ID:**`remove_ads`**(必须和代码里的 `RemoveAdsProductId` 一致);
   - 类型:**非消耗型**;
   - 价格:如 `$3.99`。
3. 启用结算:Play Console → 「创收设置」开通商家账户。

### 5.2 安装 Unity IAP

- `Window → Package Manager → Packages: Unity Registry → In App Purchasing`,装 **v4.x**(如 4.12.x)。
- 装完会提示开启 Unity IAP 服务,点同意。

### 5.3 定义编译符号

`Scripting Define Symbols` 加 `SUDOKU_IAP`。

### 5.4 代码讲解

`UnityIapService.cs` 实现 `IDetailedStoreListener`(Unity IAP 的回调接口):

1. `Initialize()`:用 `ConfigurationBuilder` 声明商品 `remove_ads`(非消耗型),然后 `UnityPurchasing.Initialize(this, builder)`。
2. `OnInitialized(...)`:商店初始化完成;若 `remove_ads` 有收据(之前买过),自动恢复 → `MarkPurchased()`。
3. `BuyRemoveAds()`:`InitiatePurchase("remove_ads")` 发起购买。
4. `ProcessPurchase(...)`:购买成功的回调 → `MarkPurchased()` → 触发 `PurchaseCompleted` 事件。
5. `Services.cs` 里已订阅该事件:`Iap.PurchaseCompleted += () => Ads.SetRemoveAds(true)`,所以买完就自动「去广告」。

### 5.5 测试

- Play Console → 设置 → 许可测试(License testing)→ 加测试账号(你的 Google 邮箱)。
- 用测试账号登录真机,购买走的是**测试订单**,不扣真钱。

## 6. 链路三:数据埋点 + 崩溃(Firebase)

### 6.1 准备:Firebase 项目和配置

1. 注册 [Firebase](https://console.firebase.google.com/) → 创建项目。
2. 添加 Android 应用,填包名(和 Play Console 一致)。
3. 下载 **google-services.json**,放进 Unity 的 `Assets/` 目录。

### 6.2 安装 Firebase + EDM4U

1. 下载 [Firebase Unity SDK](https://firebase.google.com/download/unity)(v12.x)`.unitypackage` 导入。
2. 导入后运行 `Assets → External Dependency Manager → Android → Resolve`,让它自动配置 Android 依赖。

### 6.3 定义编译符号

`Scripting Define Symbols` 加 `SUDOKU_FIREBASE`。

### 6.4 代码讲解

`FirebaseAnalyticsService.cs`:
- `LogEvent(name)` → `FirebaseAnalytics.LogEvent(name)`。
- `LogEvent(name, key, value)` → 把 `object` 转成 Firebase 支持的 `long/double/string` 类型再上报。
- `LogNonFatal(msg)` → `Crashlytics.LogException(...)` 记录非致命错误。

### 6.5 已接入的埋点事件(精简)

| 事件名 | 含义 | 参数 |
|---|---|---|
| `session_start` | 应用启动 | — |
| `services_initialized` | 服务初始化完成 | — |
| `level_start` | 开局 | `difficulty` |
| `level_complete` | 完局 | `time_sec` |
| `hint_used` | 用了提示 | — |
| `hint_rewarded_show` | 触发激励视频 | — |
| `hint_rewarded_granted` | 看完并回奖 | — |

> 完整的商业化事件字典见 [04_商业化与增长.md](./04_商业化与增长.md) §6。

### 6.6 后台看数据

Firebase 控制台 → Analytics 面板可看事件;Crashlytics 面板可看崩溃和非致命错误。

## 10. 常见坑 / 排查

1. **编译报错「找不到 GoogleMobileAds/UnityEngine.Purchasing/Firebase 命名空间」**:说明定义了符号但没装对应 SDK。先装 SDK,再定义符号。
2. **AdMob 装了 v11.x 编译失败**:v9 起事件签名从 `EventHandler<T>` 改 `Action<T>`,v11 进一步整合,
   `AdMobAdsService.cs` 需按 v11 新 API 编写(08 文档代码讲解基于 v8,仅参考逻辑;实装见 15 号文档 §2.3)。
3. **IAP 装了 v5.x**:v5 的初始化接口变化较大(统一商店、`StandardPurchasingModule.Instance(AppStore.GooglePlay)`)。建议先用 v4.x 跑通,再升级。
4. **真机看不到广告 / 广告不展示**:确认广告位 ID 正确、网络正常、已加测试设备、AdMob 账号已通过审核(新账号可能有时延)。
5. **购买失败或商品找不到**:商品 ID 必须和 Play Console 完全一致;确认已开商家账户;用许可测试账号测试。
6. **Firebase 事件不上报**:确认 google-services.json 已放 Assets、已执行 EDM4U Resolve、真机联网;首次上报可能有几分钟延迟。

## 附录:版本差异提示

- **Unity IAP v4 → v5**:v5 移除了 `IStoreListener` 旧回调体系,改为 `UnityPurchasing.Initialize` + 新的监听接口,`ConfigurationBuilder.Instance` 需传商店模块。本指南代码基于 v4。
- **AdMob v8 → v11**:v9 起事件类型从 `EventHandler<T>` 改 `Action<T>`;v10 增补事件细节;v11 整合为统一回调,
   并引入 **Android Next-Gen SDK**(要求 `MobileAds.Initialize()` 在主线程)与内置 UMP(Android 4.0 / iOS 3.1)、EDM4U 1.2.188。
   本指南代码基于 v8,真实现按 v11 官方 API 编写。

> 建议:**先用 15 号文档指定的版本跑通整条链路**,再考虑升级。升级时以官方文档为准,业务层(控制器/设置页)无需改动。
