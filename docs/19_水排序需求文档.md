## 1. 背景与目标

- 项目现状:数独玩法已跑通(模块骨架/存档/Addressables 管线/商业化链路),按 D-4 推荐"盒子多玩法"形态。
- 本玩法目标:用**经典水排序**(试管倒水、同色聚合)做第二个玩法,复用数独已验证的框架,补齐短会话休闲人群。
- **版本定位**:本玩法按 **v1.1 热更通道下发**——程序集走 HybridCLR 热更、资源走 Addressables 远程组;v1.0 首包**不包含**本玩法代码与资源,首包体积不受影响。
- **运营可调**:难度档位、关卡数值、广告频控**均不硬编码**,走配置(见 §8),后期运营可无热更调整。
- 与数独定位互补:数独=长时益智(10~20 分钟);水排序=短会话休闲(单局 1~5 分钟)。

## 2. 目标用户画像(Persona)

- **P1「通勤解压者」Emma** —— 碎片时间、不想看广告、界面干净。
- **P3「挑战型玩家」Lena** —— 关卡推进、星星/成就、每日挑战。
- **P4「地铁消磨者」Sam(新增,水排序主人群)** —— 20~30 岁通勤族,单局 1~3 分钟,喜欢"轻松但有梯度"的谜题,卡关时愿意看激励视频换道具。

---

## 3. 竞品摘要(市场定位依据)

| 竞品 | 优势 | 本项目可攻击点 |
|---|---|---|
| **经典水排序(IEC Global 系)** | 玩法先发、模板成熟、关卡海量 | 体验粗糙、广告频繁、无每日挑战沉淀 |
| **Block Blast(商业化参照)** | 激励视频点位设计教科书级(失败重试/日常奖励/道具) | 玩法不同,不直接竞争 |
| 各类水排序克隆 | 免费量大 | 质量参差、广告轰炸 |

**定位结论**:玩法用水排序标准规则(先经典后变体)+ **Block Blast 式商业化节奏**(点位密度高但尊重玩家:激励永不强制、插屏强频控、频控全部运营可调)。

## 4. 范围界定(MoSCoW)

- **Must(P0)**:经典水排序关卡(首发 ≥100 关)、3 档难度(**档位数值走运营配置**)、关卡制推进、撤销/重置、卡关保护(提示/额外空瓶)、金币奖励、激励视频(额外瓶/提示/翻倍)、去广告 IAP、每日挑战、隐私政策/UMP、基础埋点、离线可玩、引导(≤3 步)。
- **Should(P1)**:插屏广告(关卡间,**频控走运营配置**)、更多难度档位、关卡星级、成就、主题/深色、多语言、统计面板。
- **Could(P2)**:无尽模式、彩虹变体、GPGS 排行榜/云存档、订阅、皮肤商店。
- **Won't(本期)**:社交/对战、UGC 关卡编辑器、自建账号。

## 5. 功能需求清单(带验收标准)

> 编号格式 `WS-xx`(与数独 FR-xx 区分);每条含优先级与 AC。

### 5.1 核心玩法

**WS-01 经典试管倒水对局** · P0
- AC:给定 N 支试管(N = 颜色数 + 2 空管,数值走配置),每管 4 层液体;点击源管→目标管,顶端液体倒入,须满足"目标管顶同色且未满";同色液体全部聚到同一试管即过关。
- AC:动画流畅(倒水 0.3~0.5s),操作反馈(选中高亮/不能倒时抖动+音效)。

**WS-02 关卡生成与可解性保证(核心算法资产)** · P0
- AC:每关**必须可解**(由解终态反向洗牌生成或正向求解验证);单关生成耗时 Editor ≤ 200ms / 真机 ≤ 500ms;预生成题库 + 运行时生成混合方案。

**WS-03 难度体系(配置驱动)** · P0
- AC:**档位数、每档颜色数区间、关卡序号-难度映射一律读配置**(默认表 + Remote Config 下发),代码不硬编码任何档位数值。
- AC:默认参考值(Easy 3~4 色 / Medium 5~7 色 / Hard 8~10 色;前 10 关 Easy、11~30 关 Medium、31+ 关逐步 Hard)——作为本地默认表,运营可覆盖。
- AC:新增/修改配置后无需重新出包即可生效(v1.1 热更配置通道)。

**WS-04 顺序推进与解锁(关卡制)** · P0
- AC:按序号顺序解锁;过关解锁下一关;进度持久化到 `watersort.*` 存档分区;重进恢复至最新未过关卡。

**WS-05 撤销 / 重置 / 重新开局** · P0
- AC:撤销回退最近一次倒入;一键重置当前管;重开当前关;撤销/重置不造成不可解死局(保留解路径或重新生成)。

**WS-06 卡关保护(提示 / 额外空瓶)** · P0
- AC:检测卡关(无合法操作或超时)提供:①提示=自动执行一步最优倒入 ②额外空瓶=追加 1 支空管(上限由配置控制);两者为激励视频点位(WS-12)。
- AC:提示/额外瓶次数上限读配置,运营可调。

**WS-07 完成判定与结算** · P0
- AC:最后一管同色聚合→胜利动画→结算弹窗(用时、步数、金币奖励、下一关入口)。

**WS-08 金币奖励(共享 D-5 单货币)** · P0
- AC:首通奖励金币(数值走配置,默认随关卡递增 20~100);金币与数独共用 `box.coins` 存档键;消耗点位(额外空瓶/提示)数值走配置。

### 5.2 进度与留存

**WS-09 每日挑战(Daily Challenge)** · P0
- AC:每天 1 关固定种子挑战(按日期种子,全球同日同题);完成后计入连续天数 Streak;补签(P1,激励视频)。

**WS-10 统计面板** · P1
- AC:已通关数、总用时、总步数、每日挑战连胜;数据持久化到 `watersort.*` 分区。

**WS-11 成就(复用数独成就框架)** · P1
- AC:≥8 个成就(首通/连过 N 关/不用撤销过 10 关/每日挑战 7 连等)。

### 5.3 系统与体验

**WS-12 商业化(广告,频控运营可调)** · P0(激励)/ P1(插屏)
- AC(激励):三个点位——额外空瓶(默认 ≤2 次/关)、提示(默认 ≤3 次/关)、结算翻倍金币(默认 1 次/关);**各点位次数上限读配置**,运营可调;展示前完成 UMP 同意;奖励真实发放;去广告用户可无限制用(或按配置上限)。
- AC(插屏):关卡完成返回关卡选择时展示;**频控间隔读配置**(默认 ≥4 分钟 1 次);冷启动保护(新用户前三关不展示)。

**WS-13 去广告 IAP(共享)** · P0
- AC:与数独共用同一 Remove Ads 非消耗商品;购买一次两玩法都生效;支持恢复购买。

**WS-14 新手引导(Onboarding)** · P0
- AC:首次启动 ≤3 步(点击倒水/同色聚合/卡关求助),可跳过;引导期间无广告;引导步数走配置。

**WS-15 主题与深色模式** · P1 —— 复用数独主题框架;液体颜色须与主题联动。

**WS-16 设置** · P0 —— 音效/BGM/震动开关、重置本地进度、隐私政策入口、删除本地数据、语言切换(P1 启用)。

**WS-17 本地化(i18n)** · P1 —— 首期英文可发布 + 中文开发文案;文案走 L10n 表。

**WS-18 离线游玩** · P0 —— 断网完整可玩;广告位断网时优雅降级(不卡死、不白屏)。

**WS-19 无障碍** · P2 —— 色盲安全(液体颜色 + 当前高度双重编码,不纯靠颜色);热区 ≥44dp。

### 5.4 版本与发布(热更)

**WS-20 v1.1 热更下发** · P0
- AC:v1.0 首包不含本玩法代码与资源;v1.1 通过热更通道下发:程序集 `Box.HotUpdate.WaterSort` 走 HybridCLR 热更 dll,资源(prefab/美术)走 Addressables 远程组。
- AC:资源独立远程组 `Game_WaterSort`,预算 ≤8MB;构建 Profile 与更新组按 11 文档 §3.3 配置。
- AC:玩法程序集按 13 文档 §4.4 拆分,同一套代码兼容"AOT 随包 / 热更下发"两种出包模式(开发期可随包验证)。

### 5.5 技术约束(新增玩法纪律,13 号文档 §4)

- 玩法独立程序集 `Box.HotUpdate.WaterSort`,只依赖 `ModuleFramework` / `Services.Abstractions` / `UI` / `UniTask` / TMP,**不反向引用壳层与其他玩法**。
- prefab 进 Addressables `Game_WaterSort` 远程组,地址 `UI/WaterSortView`,**不进 Resources**。
- `ModuleCatalog.asset` 走 `Phase45ModuleSetup.AddEntry` 加 1 条(`id=watersort`),大厅 More Games 弹窗自动出现,大厅零改动。
- `link.xml` 保留入口类型(IL2CPP 防线)。
- 存档分区:`watersort.*` 键;金币共享 `box.coins`。

## 7. 完成标准(Definition of Done)

1. 玩法全部 AC 通过(含 WS-20 热更链路验证);
2. 无 P0/P1 缺陷;
3. 规则/生成器纯逻辑可单测(EditMode:可解性、倒水规则、难度区间、配置读取);
4. 埋点按 04 文档 §5 字典接入;
5. EditMode 全量回归 ≥ 基线 139 用例不下降;
6. 热更构建验证:远程组 AAB/更新包构建成功,增量 ≤8MB,v1.0 首包 ≤60MB;
7. 真机冒烟(热更后):大厅 → 进水排序 → 过关 → 回大厅 → 再进(≥2 轮,验证无状态残留)。
