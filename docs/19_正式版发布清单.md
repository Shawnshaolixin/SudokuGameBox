## 0. 发布路径（先看这个，决定其余项的先后）

```
生产权限获批
   ↓
出 v17（含下方 §1 全部代码改动 + 真实广告位）
   ↓
上传 Play Console → 生产轨道 → 灰度 20%
   ↓
商店页对公众公开 ← ★ 关键解锁点
   ↓
AdMob 后台「添加商店链接」→ 等就绪度审核获批
   ↓
广告自动开始填充（真 ID 已在包里，无需再发版）
   ↓
观察崩溃率/评分 → 20% → 50% → 100%
```

**★ 关键点**：AdMob 就绪度审核的前提是商店页公开可访问，而商店页只在生产轨道上线后才公开。
所以**不能等 AdMob 批准再发版**——那样永远等不到。正确顺序是**先发版带真 ID，再关联 AdMob**。

**A1 为什么现在就切真位（决策理由，勿反复）**

真 ID 在 AdMob 审核通过前只是「无填充」，审核通过后**自动开始出广告，不用再发一版**；
测试位在正式包里永远是零收入，且必须重新发版才能切。真位严格更优。

无填充时激励按钮走 [`hint.ad.unavailable`](../GameBox/Assets/HotUpdate/Sudoku/GameplayView.cs) toast 兜底，
不白屏不卡死，体验可接受。

**A3 的参数设计**

| 事件 | 参数 |
|---|---|
| `sudoku_level_start` | `difficulty` / `source`(daily\|free) |
| `sudoku_level_complete` | `difficulty` / `time_sec` / `stars` / `mistakes` / `hints_used` / `source` |
| `sudoku_hint_used` | `hint_type`(normal\|ad) |

> **不报 `puzzle_id`**：本作谜题由 `SudokuGenerator` 程序化生成，没有题库 ID。
> 04 文档 §6.1 原列了该字段，属设计时未落地的假设，**以代码现实为准**，不要为了对齐文档编一个假值。

**新增的广告/内购事件名**

| 事件 | 参数 |
|---|---|
| `ads_revenue` | `format`(rewarded\|interstitial) / `value_micros` / `currency` |
| `ads_impression` | `format` |
| `ads_click` | `format` |
| `ads_show_failed` | `format` / `reason` |
| `iap_purchase_start` | `product` |
| `iap_purchase_complete` | `product` / `source`(purchase\|restore) |
| `iap_purchase_failed` | `product` / `reason` |

> **内购漏斗的关键细节**：Google Play 对非消耗品**启动时也会回调 `ProcessPurchase` 做自动恢复**，
> 光看回调分不出「用户新购」还是「启动恢复」。代码用 `_purchaseRequested` 标记位区分，
> 且**幂等分支不上报**——否则每次启动都会虚增一笔购买转化。

### 2.2 数独生成器兜底会返回「满盘」

- 位置：[SudokuGenerator.cs](../GameBox/Assets/Core/SudokuCore/SudokuGenerator.cs) `if (!SudokuSolver.HasUniqueSolution(puzzle)) puzzle = solution.Clone();`
- 问题：`solution.Clone()` 是**没有任何空格的终盘**，触发时玩家拿到一局开局即完成、无格可填的谜题
- 且**无日志、无埋点、无计数器**，触发了你也不会知道
- 注释写「兜底再校验一次」，语义与实现不符
- [ ] 至少加日志 + 埋点；最好改为重新挖洞/重试

### 2.3 正式版日志量

- 现状：运行时 91 处 `Debug.Log` / 44 处 `Debug.LogWarning` 进包
- 前排：`AdMobAdsService`(30) / `UnityIapService`(14) / `StubServices`(12) / `ModuleLoader`(8) / `SaveService`(7)
- 影响：真机 logcat 噪音；每次广告加载都打日志有真实开销
- [ ] 加一层日志门面（`#if DEVELOPMENT_BUILD` 或 `BoxLog.Verbose`），Release 包只留 Warning/Error

### 2.4 `StubServices.cs` 死代码进包

- 现状：该文件**全文件零 `#if` 保护**，桩类始终参与编译，带 12 处日志
- 只靠 [AppBootstrap.cs](../GameBox/Assets/Gameplay/AppBootstrap.cs) 的 `#if` 选择不实例化
- [ ] 加反向 `#if`（如 `#if !SUDOKU_ADMOB`）包住对应桩类
